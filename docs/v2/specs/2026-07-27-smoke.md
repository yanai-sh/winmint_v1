# Spec: WinMint v2 Smoke vertical

**Date:** 2026-07-27  
**Status:** Ready for local tickets (`.scratch/winmint-v2-smoke/`)  
**Authority:** seed `CONTEXT.md`, `docs/STACK.md`, `docs/ARCHITECTURE.md`, ADR-002/003/004  
**Destination:** Hyper-V Smoke green — Provisioning Supervisor Shell tenure with in-process splash + DMA **hard**-field evidence

## Problem Statement

WinMint needs a greenfield ISO → unattended Hyper-V install → FirstLogon path that users and maintainers can trust. Today’s pain is guest/runtime reliability (Explorer before splash, DMA settle races, sticky intermediate failures), not host Profile typing. Smoke must prove plumbing with the same product standards bare metal will use — not a Hyper-V-only fork.

## Solution

Ship a clean-sheet v2 stack: unelevated C# Orchestrator/CLI, thin elevated host PowerShell Servicing, and a single Native AOT Provisioning Supervisor on the guest (`--machine-setup` + Winlogon Shell). In-process splash, DMA settle by final snapshot, C# child-process provisioning jobs, Shell-tenure lock, checkpoint reboot, fail-open to Explorer. No guest PowerShell. Smoke uses the fast image-quality lane and a stub job set; the executor and settle rules match production.

## User Stories

1. As a maintainer, I want a clean-sheet Profile contract, so that Smoke builds are not tied to v1 BuildProfile/InstallPlan.
2. As a maintainer, I want an unelevated C# CLI to plan a build and invoke Servicing, so that elevation is limited to imaging kernels.
3. As a maintainer, I want thin elevated Servicing kernels to mount/stage/export and stamp Shell offline, so that the guest binary is present before first logon.
4. As an installer (Local+autoLogon), I want Machine setup to stamp my account and verify Shell → Supervisor, so that I never hang on `defaultuser0` / “Just a moment.”
5. As an installer, I want the first session UI after auth to be the WinMint splash (Supervisor as Shell), so that Explorer is not the first paint.
6. As an installer with DMA on, I want visible locale/GeoID/time zone restored before installs, so that Ireland Setup does not leak into daily use.
7. As an installer, I want location-services mismatches to warn without blocking FirstLogon, so that flaky location posture does not skip useful work.
8. As an installer, I want hard DMA settle failure to show a failed splash then unlock Explorer, so that I am not trapped without evidence.
9. As a maintainer, I want provisioning jobs driven as child processes by the Supervisor, so that Smoke and metal share one executor.
10. As a Smoke runner, I want a stub job set (no real WSL), so that Hyper-V acceptance stays plumbing-focused.
11. As an installer, I want reboot-required work to checkpoint and keep Supervisor as Shell, so that splash resumes without an Explorer flash.
12. As an installer, I want unlock on complete/failed/timeout, so that Shell tenure always ends.
13. As a maintainer, I want in-memory splash status plus JSON evidence snapshots, so that VM harness can pull proof without a file control plane.
14. As a Smoke runner, I want fast image-quality builds by default, so that iteration is not blocked by Max compression.
15. As a maintainer, I want acceptance to assert splash + DMA hard fields, so that plumbing green means real settle success.
16. As a product owner, I want no Avalonia/WebView2 on the ISO, so that guest UI stays a thin AOT presenter.
17. As a legal/product owner, I want the Source ISO always user-supplied, so that WinMint never redistributes Windows media.

## Implementation Decisions

- Product languages: C# for CLI, Orchestrator, and all guest FirstLogon/Machine setup; PowerShell 7.6+ for host Servicing only.
- One guest AOT binary: `WinMint.Provisioning` (`--machine-setup` and Shell); splash in-process (Direct2D/GDI with fallback).
- Shell registration: Servicing stamps offline; Machine setup fail-closed verifies/restamps (with autologon stamp).
- DMA settle: bounded restore then final snapshot; hard locale/GeoID/TZ; soft location; same Smoke and metal.
- Provisioning jobs: Supervisor runs winget/Scoop/wsl (etc.) as child processes; Smoke stub job set.
- Status: in-memory for paint; JSON snapshots for evidence only.
- Fail-open: unlock on `complete`/`failed` (short failed dwell) and wall-clock timeout; hold Shell on `reboot` with durable checkpoint.
- Theme: splash-owned canvas; apply Profile appearance once before Explorer unlock.
- Provisioning lock: Shell tenure; hard input lockdown later, not Smoke-critical.
- Image quality: run override; Smoke uses fast lane; report records what ran.
- Clean-sheet Profile/unattend/job contracts; no v1 schema migration.
- NuGet Microsoft-thin (source-gen JSON, System.CommandLine, xUnit); Avalonia later for host wizard only.

## Testing Decisions

- Test external behaviour, not private method structure.
- Prefer few high seams: (1) Orchestrator Profile/plan/unattend contracts; (2) Supervisor phase machine (settle → jobs → unlock/reboot); (3) Hyper-V Smoke acceptance evidence (highest product seam).
- Unit/contract tests for Orchestrator and settle/job phase rules where deterministic.
- VM Smoke proves: Machine setup stamps, Shell tenure splash, DMA hard fields green (or failed path with evidence), unlock, fast-lane ISO used when configured.
- Prior art: v1 VM acceptance evidence folders and contract suites — behaviour reference only; new schemas in v2.

## Out of Scope

- Avalonia wizard
- Debloat / keep-flag matrix
- BitLocker / device-encryption policy
- Physical hardware acceptance
- Guest PowerShell FirstLogon runtime
- Peer Splash.exe
- C#-only in-process DISM as default
- v1 BuildProfile / InstallPlan / PowerShell CLI compatibility
- Full metal package matrix (browsers, real WSL, pins polish)
